## 目的

`include` / `component` を親ドキュメントへ差し込むとき、挿入位置の直前見出しに合わせて取り込み側の見出しレベルをずらし、文書全体の見出し階層が崩れないようにする。

---

## 決定事項

| 項目 | 内容 |
|------|------|
| 対象 | **`include` と `component` の両方** |
| component 出力行数 | **多行を許可**する（現行の単行制限・`component_multiline_output` は廃止） |
| 取り込み側の書き方 | 見出しは常に **`#`（レベル 1）から始める**（相対レベルで書く） |
| シフト基準 | **挿入位置の直前見出し**のレベル `L` |
| 変換式 | 取り込み側の見出しレベル `H` → `min(6, H + S)`（下記の `S`） |
| ネスト | **オフセット累積**（親から子へ `O` を引き継ぎ、挿入ごとに加算） |
| 深さ上限 | **常に見出し 6 が最深**。`H + S > 6` でも `######` にクランプ（エラーにしない） |
| 見出し判定 | **ATX（`#`〜`######`）と Setext（`===` / `---`）の両方** |
| 除外 | **コードフェンス（`` ``` `` / `~~~`）内**の行は見出しとみなさない |

## オフセットとシフト

### 用語

| 記号 | 意味 |
|------|------|
| `O` | 親から渡された **累積オフセット**（エントリ文書は `0`） |
| `L` | 挿入位置より前にある **直近見出し**のレベル（1〜6）。直前見出しが無いときは `0` |
| `S` | 当該挿入のシフト量。`S = O + L` |
| `H` | 取り込みドキュメント上の著者見出しレベル（1〜6） |

### 規則

1. エントリ（ルート）文書のレンダー開始時、`O = 0`
2. `include` 展開または `component` 呼び出しの挿入ごとに、親バッファ上の挿入位置について `L` を求め、`S = O + L` とする
3. 子ドキュメントをレンダーするとき、子へ **`O' = S`** を渡す（ネストで累積）
4. 子内の各見出しは出力時に `H' = min(6, H + S)` へ変換する  
   （子のネストした include / component は、子内の `O' = S` を起点に同様に計算する）
5. `H' > 6` にはしない。クランプ時も警告・エラーは出さない

### 例

親:

```markdown
# Page

## Section

include ./child.md
```

`child.md`（常に `#` から書く）:

```markdown
# Child title

## Child sub
```

- 挿入位置の直前見出しは `##` → `L = 2`、`O = 0` → `S = 2`
- 出力:

```markdown
# Page

## Section

### Child title

#### Child sub
```

### ネスト（オフセット累積）の例

`child.md`:

```markdown
# Child title

include ./grand.md
```

`grand.md`:

```markdown
# Grand title
```

- 親 → child: `O=0`, `L=2`, `S=2` → child の `#` は `###`
- child → grand: 子に渡す `O'=2`、grand 挿入直前の見出しは child 上の `#` → `L=1`、`S=2+1=3`
- grand の `#` → `####`

### 直前見出しが無い場合

文書先頭の `include` / `component` など、前方に見出しが無ければ `L = 0`。`O = 0` ならシフトなし（著者レベルどおり）。

### レベル 6 クランプの例

直前が `#####`（`L=5`）で、取り込み側に `##`（`H=2`）があるとき: `2+5=7` → **`######`**。

取り込み側に `#`〜`######` が混在していても、それぞれ独立に `min(6, H + S)` する（相対差が潰れることは許容）。

## 見出しの検出

シフト対象・`L` 計測の両方に同じ規則を使う。

### ATX

- 行頭（任意の先頭空白のあと）の `#` が 1〜6 個、その直後が空白または行末
- 閉じの `#` があってもレベルは先頭の個数
- 7 個以上は見出しとみなさない（CommonMark に合わせる）

### Setext

- テキスト行の次行が、空白を除き `=` のみ → レベル **1**
- テキスト行の次行が、空白を除き `-` のみ → レベル **2**
- Setext をシフトするときは **ATX に正規化して出力**する（例: Setext レベル 1 を `S=2` でシフト → `### テキスト`）
  - 理由: シフト後のレベル 3 以降を Setext では表現できないため

### コードフェンス

- 開きフェンス（`` ``` `` または `~~~`、情報文字列可）から、対応する閉じフェンスまでを **無視**
- フェンス未閉じの場合は、開き以降 EOF まで見出し対象外
- インデント付きフェンスも通常の Markdown 同様に扱う（実装は既存パーサ方針に追随）

### 対象外（この版では見ない）

- HTML の `<h1>`〜`<h6>`
- 参照リンク定義やその他の非見出し構文

## パイプライン上の位置

現行処理順（[pipeline.md](../../specs/pipeline.md)）を維持したまま、次を追加する。

| 段階 | 見出しシフト |
|------|----------------|
| step 4 `include` 展開 | 各 `include` 置換時に `L` / `S` を計算し、子レンダーへ `O'=S` を渡す。展開結果の見出しをシフトして埋め込む |
| step 6 `{{ }}`（component） | 各 component 呼び出し位置で同様。多行結果をそのまま埋め込み可 |

補足:

- `extend` / `block` 自体は本機能の直接対象外（block 本文に書いた include / component は、マージ後の位置で通常どおり対象）
- `if` / `each` 展開後の本文に残った include は step 4 では既に処理済み。component は step 5 のあと step 6 で処理し、その時点のバッファで直前見出しを見る

## component 単行制限の廃止

| 現行 | 本計画 |
|------|--------|
| 改行を含む component 出力 → エラー `component_multiline_output` | **許可**。エラーコードは廃止（投げる処理・メッセージ定義・テスト仕様から削除） |

`include` は従来どおり多行可。見出しシフトだけが新規。

## 受け入れ条件

- [ ] `include` 挿入で、直前見出しレベルに応じて取り込み側 ATX / Setext 見出しがシフトされる
- [ ] `component` 挿入でも同様（**多行 component がエラーにならない**）
- [ ] ネストした include / component でオフセットが累積される
- [ ] `H + S > 6` のとき `######` にクランプされ、エラー・警告にしない
- [ ] コードフェンス内の `#` や Setext 風の行は、`L` 計測にもシフト対象にも使わない
- [ ] Setext 見出しはシフト後 ATX に正規化される
- [ ] `component_multiline_output` が API・メッセージ・実装から除かれる
