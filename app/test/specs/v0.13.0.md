# v0.13.0 テスト仕様書

[roadmap v0.13.0](../../docs/roadmap.md) の CLI 範囲に対応する。製品計画の正本は [docs/specs/cli.md](../../docs/specs/cli.md)（旧 `docs/plans/v0.13.0/cli-dev-server.md`）。既存ライブラリ API は [docs/specs/api.md](../../docs/specs/api.md) が正。

関連 Issue:

- [#35](https://github.com/b4moss/hyogen-md/issues/35) — `create` / `hyogen.config` / `build` CLI
- [#30](https://github.com/b4moss/hyogen-md/issues/30) — 執筆用 `dev` サーバ

## スコープ

- **単一 CLI** `hyogen-md`（`@b4moss/hyogen-md` の `bin`）: サブコマンド `create` / `dev` / `build`
- **`defineConfig` / `loadConfig`** — `hyogen.config.(js|ts)` の読込（`@b4moss/hyogen-md/config`）
- **`create`** — 最小プロジェクト生成（js/ts 選択、既定 js）
- **`build`（CLI）** — 設定を既存 `build()` API に渡して `outDir`（既定 `./out`）へ出力
- **`dev`** — HTTP プレビュー（ファイルツリー＋プレビュー専用 UI）、ファイルウォッチ、ファイル単位 HMR、診断はターミナル
- ライブラリ公開 API（`renderServer` / `renderClient` / `build`）のシグネチャは変更しない

## スコープ外（本テスト仕様）

| 項目 | 扱い |
|------|------|
| 許可メソッド追加（`.slice` 等） | 同マイルストーンの別 Issue。本仕様の対象外 |
| `preview` サブコマンド | 非目標 |
| ブラウザ上のソース編集・ディスク書き戻し | 非目標 |
| ブラウザ診断オーバーレイ | v1 非必須 |
| 式／ブロック単位 HMR | v1 非対象 |
| Playground / docs-site の UI 流用 | 対象外（役割分離） |
| `marked` 等のプレビュー変換をライブラリ主 export に載せる | 禁止（`dev` 専用） |
| E2E（実ブラウザ自動操作） | MVP では必須としない（HTTP／HMR の結合で代替） |

## 確定事項（v0.13.0 / CLI）

| 項目 | 確定内容 |
|------|----------|
| パッケージ | `@b4moss/hyogen-md`（既存）に CLI を同梱 |
| バイナリ名 | `hyogen-md` |
| 設定ファイル名 | `hyogen.config.js` / `hyogen.config.ts`（探索順は実装で固定し本仕様に明記） |
| 設定記法 | `defineConfig({ ... })` の default export |
| 必須キー | `input` のみ |
| `outDir` | 任意。未指定時 **`./out`**。`dev` は書き出さない |
| create 言語選択 | `js` / `ts`。**既定 `js`** |
| create 生成物 | `package.json` / `hyogen.config.(js\|ts)` / `src/index.md` / `.gitignore` |
| `dev` UI | ファイルツリー＋プレビューのみ（編集ペインなし） |
| `dev` レンダー | 実ディスク + `renderServer`（メモリ保持）。`build()` による `outDir` 書き出しはしない |
| HMR | 変更ファイルと依存（include / component / extend 等）の影響エントリを再レンダーし、フルリロードしない |

## Phase 1: defineConfig / loadConfig（#35）

### defineConfig

- `HyogenConfig` オブジェクトを受け取り、同一参照または同等の設定オブジェクトを返す（型支援・将来の正規化の入口）
- 副作用なし
- 公開 export: `@b4moss/hyogen-md/config`

#### テスト: 正常系

- `{ input: "./src/**/*.md" }` を渡すと、返却値に同じ `input` が含まれる
- `{ input: "./src/index.md", outDir: "./dist-md" }` を渡すと両キーが保持される
- 追加の任意キー（例: `context: { site: "x" }`）を渡しても落とさない（v1 ではパススルー可）

#### テスト: 異常系

- （実行時バリデーションを `defineConfig` に持たせる場合）`input` 欠落 → 設定エラー（コードは実装で定義し、本仕様では「必須欠落として失敗」と固定）
- `input` が空文字 → 設定エラー
- `input` が `null` / 非文字列・非配列 → 設定エラー
- バリデーションを `loadConfig` 側に寄せる場合は、本関数の異常系は省略し `loadConfig` で担保する（どちらか一方に集約）

### resolveConfigPath

- 探索ディレクトリ（既定: `cwd`）から `hyogen.config.*` の実在パスを返す
- 探索候補（固定）: `hyogen.config.ts` / `hyogen.config.js` / `hyogen.config.mjs` / `hyogen.config.cjs`（**優先順位を実装で 1 つに決め、ここにも同じ順を書くこと**。初期案: `.ts` → `.mjs` → `.js` → `.cjs`）
- 見つからなければエラー

#### テスト: 正常系

- `hyogen.config.js` のみあるディレクトリ → その絶対パス
- `hyogen.config.ts` のみ → その絶対パス
- 複数ある場合 → 優先順位どおり最優先の 1 件

#### テスト: 異常系

- 設定ファイルが無い → 設定未検出エラー
- 探索対象がファイルではなくディレクトリとして無効（存在しない cwd）→ エラー
- 同名だが読めないパス（権限など）は結合で任意カバー

### loadConfig

- `resolveConfigPath` で得たファイルを読み、default export を `HyogenConfig` として返す
- `.ts` / `.js` を読める（`jiti` 等）
- `input` 必須を検証。`outDir` 未指定時は呼び出し側で `./out` を補うか、返却前に正規化して `outDir: "./out"` を入れる（**正規化後は常に `outDir` 文字列を持つ**ことを本仕様の期待とする）
- `input` / `outDir` の相対パスは **設定ファイルのディレクトリ** を基準に絶対パスへ解決して返してよい（CLI が解決してもよいが、どちらかに統一）

#### テスト: 正常系

- JS 設定（`defineConfig` + `input` のみ）→ `input` あり、`outDir` が `./out`（または絶対パス化された同等）
- TS 設定を読める
- `outDir` 明示時はその値が使われる
- `input` が文字列配列でも受理する（既存 `build()` に合わせる）

#### テスト: 異常系

- `input` キーなし → エラー
- default export がオブジェクトでない → エラー
- 設定ファイルが syntax error → エラー（読込失敗）
- 空ファイル / export なし → エラー
- 対応外拡張子のみしか無い場合は `resolveConfigPath` 側で既に失敗

## Phase 2: CLI `build`（#35）

### runCliBuild

- cwd（または `--config`）から `loadConfig` し、既存 `build({ input, outDir, ... })` を呼び出す
- 成功時: `outDir` 以下に Markdown が書き出される
- warnings はターミナルに出力する（フォーマットは既存診断に寄せる）
- ライブラリの `build()` シグネチャは変えない

#### テスト: 正常系

- 最小プロジェクトで `runCliBuild` → `outDir`（既定相当）にエントリの `.md` が存在する
- 設定で `outDir: "./dist-md"` → そのディレクトリに出力され、既定 `./out` には書かない
- include 付きページを build すると、展開後 Markdown が出力に反映される

#### テスト: 異常系

- 設定ファイル無し → 非 0 終了相当のエラー（例外または Result）
- `input` にマッチするファイルが 0 件 → 既存 `build()` の振る舞いに従う（空成功 or エラー。**既存仕様に合わせ、ここに期待を追記して固定**）
- 出力先が書けない（権限・ファイル衝突）→ エラー
- レンダーエラー（故意に壊したテンプレート）→ エラーが伝播し、プロセスは成功扱いにしない
- 不正な CLI 引数（未知オプション）→ 使い方エラー

## Phase 3: CLI `create`（#35）

### runCliCreate

- 指定ディレクトリ（既定: cwd または引数のターゲット）に最小構成を生成する
- 言語: 引数またはプロンプト相当の選択肢。テストでは **非対話 API**（例: `{ language: "js" | "ts" }`）を通し、既定は `"js"`
- 生成後、依存インストールは必須としない（package.json に `@b4moss/hyogen-md` を書くところまで）
- 既存非空ディレクトリへの上書きは失敗させる（安全側）

#### テスト: 正常系

- `{ language: "js" }` → `hyogen.config.js` / `package.json` / `src/index.md` / `.gitignore` が存在する
- `{ language: "ts" }` → `hyogen.config.ts` が存在し、`.js` 設定は作らない
- `package.json` の `scripts` に `dev` と `build` が含まれる
- 生成された JS 設定を `loadConfig` で読める（中身が `defineConfig` + `input`）

#### テスト: 異常系

- ターゲットが既存ファイル → エラー
- ターゲットが非空ディレクトリ → エラー
- 書けない場所（権限）→ エラー
- `language: "coffee"` など不正値 → エラー
- 親ディレクトリが存在しない → エラー

## Phase 4: tree / preview 変換（#30）

### buildFileTree

- 設定の `input` からプレビュー対象ファイル一覧（ツリー用 JSON）を返す
- エントリ方針は既存 `build` / `collectEntryPaths` に合わせる（`_` partial の扱いは既存ルール踏襲）
- 各ノードは少なくとも相対パス（またはプロジェクト相対パス）とファイル/ディレクトリ種別を持つ

#### テスト: 正常系

- `src/index.md` と `src/about.md` がある → 両方リストされる
- ネストしたディレクトリがツリー構造で表現される
- `_partial.md` がエントリから除外される場合、ツリーの「選択可能エントリ」にも出ない（ディレクトリ表示方針は実装に合わせ明記）

#### テスト: 異常系

- `input` 配下が空 → 空ツリー（エラーにしない）または明示エラー（**空配列を返す**に固定）
- 存在しない root → エラー
- ファイルではなく壊れた symlink 等 → スキップまたはエラー（実装で固定し 1 ケース以上）

### renderPreviewMarkdown

- 指定エントリパスを `renderServer`（+ Node loader）でレンダーし、**Markdown 文字列**と warnings を返す
- ディスクの `outDir` には何も書かない

#### テスト: 正常系

- 単純な `index.md` → 期待する Markdown 断片を含む
- include あり → 部分が展開された Markdown になる
- warnings があるテンプレート → 結果と warnings 配列の両方を返す（throw しない範囲は既存 render に従う）

#### テスト: 異常系

- 存在しないパス → エラー
- レンダー失敗（構文エラー等）→ エラー（呼び出し側がターミナル出力する）
- ディレクトリパスを渡す → エラー
- `outDir` を渡しても（または内部に既定があっても）**ファイル書き出しが発生しない**ことをスパイ/一時 FS で確認
- loader 失敗 → エラー

### markdownToPreviewHtml

- `dev` 専用: Markdown 文字列 → HTML 文字列
- ライブラリの公開 export からは呼び出せない（または `cli` 内部モジュールに閉じる）

#### テスト: 正常系

- `# Title` → `h1` 相当を含む HTML
- 段落・リストが HTML になる
- 空文字 → 空または空ドキュメント相当（throw しない）

#### テスト: 異常系

- 非文字列入力 → エラー
- （HTML サニタイズを行う場合）script タグの扱いを 1 ケース固定。**行わない場合は異常系を薄くし、その旨を明記**

## Phase 5: DependencyIndex / FileWatcher / HMR（#30）

### buildDependencyIndex

- エントリ群に対し既存 `buildDependencyGraph`（または同等）を用い、**変更パス → 再レンダーすべきエントリ集合**を返す索引を構築する
- エントリ自身の変更では、そのエントリが集合に含まれる

#### テスト: 正常系

- `index.md` が ` _partial.md` を include → ` _partial.md` 変更の影響エントリに `index.md` が含まれる
- 無関係な `about.md` は影響集合に含まれない
- エントリ単体の変更 → そのエントリのみ（依存が無い場合）

#### テスト: 異常系

- 空エントリ一覧 → 空索引（クエリは常に空集合）
- 未知パスをクエリ → 空集合（エラーにしない）
- グラフ構築時に欠落 include → 既存グラフ／render のエラー方針に従う（索引構築失敗としてエラーにしてよい）

### collectAffectedEntries

- 変更された絶対/相対パス 1 件（または複数）から、再プレビュー対象エントリのリストを返す

#### テスト: 正常系

- partial 変更 → 親エントリ 1 件以上
- エントリ変更 → 自身
- 無関係ファイル変更 → 空

#### テスト: 異常系

- 空の変更リスト → 空
- 索引未初期化で呼び出し → エラー
- 重複パス → 一意なエントリ集合

### createFileWatcher（または wrap）

- 指定パス集合をウォッチし、変更イベントをコールバックへ渡す
- テストでは chokidar 実体の代わりに、イベント発火可能なフェイクでもよい（結合で 1 件は実ファイル touch を推奨）

#### テスト: 正常系

- 監視中ファイルを更新 → コールバックが当該パスで呼ばれる
- 複数パス監視ができる
- `close()` 後はイベントが来ない

#### テスト: 異常系

- 存在しないパスのみ監視開始 → エラーまたは準備完了後に無視（実装固定）
- `close()` の二重呼び出し → 安全（ throw しない）
- コールバック内例外が watcher を壊さない（任意）

### HmrHub

- 購読者へ「影響エントリ」や「再取得すべき path」を通知する（WebSocket 想定）
- サーバ側ユニットでは、接続モックへ JSON メッセージが送られることを検証

#### テスト: 正常系

- 購読者 1 人に `paths: [...]` が届く
- 購読者 0 人でも通知処理は throw しない
- 複数購読者に同内容が届く

#### テスト: 異常系

- 切断済み購読者への送信 → 除外され全体は継続
- 不正ペイロードを送ろうとした場合のガード（任意）
- `close()` 後の `publish` → no-op またはエラー（固定）

## Phase 6: DevServer / `runCliDev`（#30）

### createDevServer

- HTTP サーバを起動し、少なくとも次を提供する:
  - `GET /` — プレビュー UI（編集用 textarea/contenteditable を持たない）
  - `GET /api/tree` — ファイルツリー JSON
  - `GET /api/preview?path=` — レンダー結果（Markdown および/または HTML）
  - HMR エンドポイント（WebSocket）
- 既定ポート `4173`。占有時はエラーまたは次ポート探索（**エラーに固定**し `--port` で明示させる）

#### テスト: 正常系

- 起動後 `GET /api/tree` が 200 でエントリを返す
- `GET /api/preview?path=src/index.md` が 200 で本文を返す
- `GET /` の HTML に編集用の `textarea` / `contenteditable` が**無い**
- 一時ディレクトリを `outDir` に設定しても、dev 操作後にそのディレクトリが作成・書込されない

#### テスト: 異常系

- 設定無しで起動 → エラー
- 存在しない `path` の preview → 4xx
- ポート衝突 → エラー
- 不正な method / 未知パス → 4xx
- レンダー失敗時 → 5xx または 4xx と、ターミナル側に診断が出る（ログスパイ）

### runCliDev

- `loadConfig` → `createDevServer` → ウォッチを接続し、変更で `collectAffectedEntries` → preview 再レンダー → `HmrHub.publish`
- Ctrl+C 等で watcher / server を閉じる（結合で `close` を呼べばよい）

#### テスト: 正常系

- 起動後、エントリファイルを書き換えると HMR 通知にそのパス（または影響エントリ）が含まれる
- partial を書き換えると、include 元エントリが通知される
- 一連の操作で `outDir` にファイルが増えない

#### テスト: 異常系

- 設定欠落 → 起動失敗
- ウォッチ対象の削除でサーバ全体が落ちない（当該 preview エラー＋通知、またはツリー更新）
- `close` 後の再イベントで未処理例外が出ない
- レンダーエラー継続中でもサーバは listen し続ける

## Phase 7: CLI エントリ（cac 配線）

### runCli

- `process.argv` 相当を受け、`create` / `dev` / `build` / `--help` を振り分ける
- 未知コマンドは非 0

#### テスト: 正常系

- `["build"]` → `runCliBuild` が呼ばれる（モック）
- `["dev"]` → `runCliDev` が呼ばれる
- `["create", "--language", "js"]` → `runCliCreate` が呼ばれる
- `--help` / サブコマンド無し → ヘルプ表示相当（終了コード 0）

#### テスト: 異常系

- 未知コマンド → 非 0
- 必須引数不足（create の不正 language 等）→ 非 0
- サブコマンド内エラーが握りつぶされない

## 受け入れ条件との対応

### create / config / build（#35）

| 受け入れ | 主に担保する節 |
|----------|----------------|
| `create` で最小構成 | Phase 3 `runCliCreate` |
| js/ts 選択・既定 js | Phase 3 |
| `defineConfig` で `input` 必須を読める | Phase 1 |
| `build` が `outDir`（既定 `./out`）へ出力 | Phase 2 |

### dev（#30）

| 受け入れ | 主に担保する節 |
|----------|----------------|
| HTTP サーバ起動 | Phase 6 `createDevServer` |
| ファイルツリーから選択 | Phase 4 `buildFileTree` + Phase 6 `/api/tree` |
| 保存で依存込み HMR | Phase 5 + Phase 6 `runCliDev` |
| ブラウザで編集できない | Phase 6（`textarea` / `contenteditable` 不在） |
| `outDir` 非書き込み | Phase 4 / 6 |
| エラー／warning がターミナル | Phase 4 / 6（ログ出力） |
