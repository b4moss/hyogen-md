## Phase A: 見出しヘルパ

### findPrecedingHeadingLevel

- 入力文字列（挿入位置より前のプレフィックス）から直近見出しレベルを返す
- ATX（`#`〜`######`）と Setext（`=` / `-` 下線）を検出
- コードフェンス内は無視。見出しが無ければ `0`

#### テスト: 正常系

- `## Section\n\n` → `2`
- `# A\n## B\n` → `2`（直近）
- 文書先頭・見出しなし → `0`
- Setext（`Title\n===`）→ `1`、`Title\n---` → `2`
- フェンス内の `# Not` のあと本文に見出しなし → `0`
- フェンス閉鎖後の `### After` → `3`

#### テスト: 異常系

- `####### Too many` は見出しとみなさない（直前が無ければ `0`）
- 未閉じフェンス内の見出し風行は無視

### shiftMarkdownHeadings

- 全見出しを `min(6, H + shift)` に変換。Setext は ATX に正規化。フェンス内は不変

#### テスト: 正常系

- `shift("# A\n## B", 2)` → `### A\n#### B`
- `shift=0` は ATX をそのまま（Setext もそのまま残してよい。シフト時のみ ATX 化）
- Setext レベル 1 を `shift=2` → `### Title`
- `##### X` を `shift=3` → `###### X`（クランプ）
- フェンス内の `# Keep` は変わらない

#### テスト: 異常系

- 負の shift → 入力をそのまま返す（または実質 no-op）
- 空文字 → 空文字

## Phase B: expandIncludes

### expandIncludes（見出しシフト）

- マーカー直前のプレフィックスで `L` を求め、子 Markdown を `shiftMarkdownHeadings(..., L)` して埋め込む
- ネスト時は子内でも同様にシフトし、親が子全体をさらにずらすことで累積する

#### テスト: 正常系

- 直前 `##` + 子 `#` / `##` → `###` / `####`
- ネスト: 親 `##` → child `#` + include grand `#` → 出力で grand が `####`
- `L=0`（先頭 include）→ 子のレベルそのまま
- `L=5` + 子 `##` → `######`
- フェンス内偽見出しは `L` に効かない

#### テスト: 異常系

- 循環 include → 従来どおり警告 + スキップ（見出し処理と独立）
- 欠落ファイル → 従来どおりエラー

## Phase C: component + 多行

### renderComponent

- 改行を含む出力を許可する（`component_multiline_output` を投げない）

#### テスト: 正常系

- 2 行以上の component がエラーなく文字列を返す
- 単行 component は従来どおり動作

#### テスト: 異常系

- 未登録 alias → 従来どおり `parse_error`
- （旧）多行エラーは**発生しない**ことを回帰で確認

### interpolateExpressions（component 見出しシフト）

- `call` ノード（component）の結果だけ、蓄積済み前文で `L` を取りシフトして連結
- 通常の変数式はシフトしない

#### テスト: 正常系

- 直前 `##` のあと `{{ card({}) }}`（子が `# Title`）→ `### Title`
- 多行 component の複数見出しがまとめてシフトされる
- `{{ title }}` のような非 call は無変更

#### テスト: 異常系

- 式のパース失敗 → 従来どおり
- 未登録 component → 従来どおり
