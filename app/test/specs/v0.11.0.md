## スコープ（#37）

- **`loadDataSources(sources, options?)`** — 複数データファイルを読み、変数名 → 値の `HyogenContext` を返す（[api.md](../../docs/specs/api.md)）
- **`parseDataFile(source, path)`** — 拡張子に応じてパース（内部 API。テスト対象）
- **`dataSources` オプション** — `renderServer` / `build` で読込結果を context にマージ
- **マージ順** — `dataSources` → `context` → `serverContext`（浅いマージ、後勝ち）
- **`renderClient` 拒否** — `dataSources` 指定時は **`data_sources_on_client`**
- **#37 受け入れに必須**: YAML / JSON の単一・複数読込、欠落等のエラー、上記マージ／拒否
- v0.10.x 回帰維持

## スコープ外

| 項目 | 扱い |
|------|------|
| DSL の `import` / `require` | 引き続き禁止（[dsl.md](../../docs/specs/dsl.md)） |
| `renderClient` / `@b4moss/hyogen-md/client` への `loadDataSources` export | 禁止 |
| データファイルのリモート URL 読込 | 非対応（拒否をテストする） |
| Playground のデータ読込 UI | 対象外 |
| TOC / 許可メソッド拡張 | v0.12+ |
| **CSV の受け入れ（#38）** | パーサ実装の回帰は維持してよいが、**#37 の受け入れ条件には含めない**。CSV 専用の render/build 統合テストは #38 |
| CSV の TSV・セミコロン区切り・BOM 除去 | 将来 PATCH |

## Phase 3: loadDataSources

対象: [app/src/io/loadDataSources.ts](../../src/io/loadDataSources.ts)  
テスト: [app/test/io/loadDataSources.test.ts](../io/loadDataSources.test.ts)

### loadDataSources

- `DataSourcesMap` の各エントリを順に読込・パースし、1 つの `HyogenContext` にまとめる
- キー = 変数名、値 = ルート相対パス
- `options.root` 未指定時は cwd または `.doc_root` 探索（既存 path 解決に合わせる）
- `options.loader` 指定時は loader で文字列取得
- **パスが `http://` / `https://` のとき**は loader を呼ばず **`load_failed`**（`details.reason` にリモート非対応。既存 `isRemotePath` を利用）
- **読込後ソースが 5MB 超**なら **`data_source_too_large`**（`details.path` / `size` / `limit`。`limit = 5 * 1024 * 1024`）

#### テスト: 正常系（#37 受け入れ A1 / A2）

- [ ] `{ site: "./site.yaml" }` → `{ site: { title: "...", ... } }`（**A1**）
- [ ] 複数キー `{ site: "...", products: "..." }` → 両方のキーが context に存在（**A2**）
- [ ] `items-array.json` を `items` キーで読込 → `context.items` が配列
- [ ] 空マップ `{}` → `{}`
- [ ] 任意キー名（例: `"my-site"` / `"123"`）でも制約なく格納できる

#### テスト: 異常系（#37 受け入れ A3）

- [ ] 存在しないパス → **`file_not_found`**（**A3**）
- [ ] パース失敗 → **`parse_error`**
- [ ] loader が throw（HyogenError 以外）→ **`load_failed`**
- [ ] `https://example.com/data.yaml` → **`load_failed`**（`file_not_found` ではない）
- [ ] `http://example.com/data.json` → **`load_failed`**
- [ ] ソースが `5 * 1024 * 1024 + 1` バイト → **`data_source_too_large`**（`size` / `limit` を検証）
- [ ] ちょうど 5MB（`5 * 1024 * 1024`）→ **成功**（境界）

#### テスト: CSV（#38 / 回帰）

- [ ] `rows.csv` を `rows` キーで読込 → オブジェクト配列（既存回帰）

## Phase 4: renderServer 統合（#37 本丸）

変更: [app/src/renderServer.ts](../../src/renderServer.ts)  
テスト: 新規（例: `app/test/renderServer.dataSources.test.ts`）または既存 render テストへ追加  
fixture: `app/test/fixtures/v0.11/render/doc-root/`

### 挙動

```ts
const fromFiles = options?.dataSources
  ? await loadDataSources(options.dataSources, {
      root: options.root,
      loader: options.loader,
    })
  : {};
const merged = mergeContext(fromFiles, context, options?.serverContext);
```

- `dataSources` 未指定 / 省略時は追加読込なし
- 空オブジェクト `{}` は未指定と同義（読込ループ 0 回で可）

#### テスト: 正常系（#37）

- [ ] `from-yaml.md` + `dataSources: { site: "./data/site.yaml" }` → 本文 `{{ site.title }}` が展開（**A1**）
- [ ] `from-json.md` + `dataSources: { meta: "./data/meta.json" }` → `{{ meta.version }}` 展開（**A1**）
- [ ] YAML + JSON を同時指定 → 両方の変数が展開（**A2**）
- [ ] `merge-order.md` + `dataSources` と `context` に同名キー → **context の値**が勝つ
- [ ] `dataSources` + `serverContext` に同名キー → **serverContext の値**が勝つ
- [ ] `dataSources` 未指定 → v0.10.x 回帰（従来どおり）

#### テスト: 異常系（#37 / A3）

- [ ] 欠落 data ファイル → **`file_not_found`**（render 中断）
- [ ] 壊れた JSON → **`parse_error`**
- [ ] リモートパスを dataSources に指定 → **`load_failed`**
- [ ] 過大ファイル → **`data_source_too_large`**

#### テスト: CSV（#38）

- [ ] `from-csv.md` + `rows.csv` → `{{ rows.0.name }}` 展開 — **#38 で実施**

## Phase 5: build 統合

変更: [app/src/build/build.ts](../../src/build/build.ts)  
テスト: 新規（例: `app/test/build.dataSources.test.ts`）  
fixture: `app/test/fixtures/v0.11/build/doc-root/`

### 挙動

- エントリ収集の後、**各エントリ render の前に 1 回** `loadDataSources`
- 全エントリで同一のマージ済み context を使う（二重読込しない）
- `renderServer` に既マージ context を渡す場合は、エントリごとに `dataSources` を再実行しないこと

#### テスト: 正常系（#37）

- [ ] `build({ input, outDir, dataSources: { config: "./data/config.yaml" } })` → 出力 Markdown に `{{ config.env }}` が展開（**A1**）
- [ ] 複数エントリ（`index.md` / `about.md`）で **同一** data 値が使われる（**A2**）
- [ ] `dataSources` 未指定 → v0.10.x build 回帰

#### テスト: 異常系（#37 / A3）

- [ ] 欠落 data → **`file_not_found`**（build 中断、成果物を部分書き出ししない／既存 build エラー方針に合わせる）
