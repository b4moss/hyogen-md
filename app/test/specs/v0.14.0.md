## スコープ

- **コードフェンス内の `${expr}` 展開** — JS テンプレートリテラルと同型の振る舞い（本文マスタッシュ `{{ }}` とは別系統）
- 対象フェンス: `` ``` `` および `~~~`（CommonMark 寄りの開閉規則。実装は `createFenceState` / `consumeFenceLine` を再利用）
- 式: 許可式のみ。`.toLocaleString` / `.length` 可。**component 呼び出し不可**（`allowCalls: false`）
- エスケープ: `\${` は展開しない（JS と同じ）
- パイプライン配線: `interpolateExpressions`（`{{ }}`）の直後。`expandEach` 内でも同順（each 束縛をフェンス内から参照可能に）
- v0.13.0 回帰維持

## スコープ外（v0.14.0 / #125）

| 項目 | 扱い |
|------|------|
| フェンス**外**の本文 `${}` | リテラルのまま。本 Issue 対象外 |
| `{{ }}` / `{{{ }}}` の挙動変更 | 対象外（フェンス内でも現状どおり展開される） |
| Playground / docs-site のハイライト | 別 Issue |
| 公開 API シグネチャ変更 | なし |
| `@hg` 内 `` `…${}…` `` | 既存（v0.7）。本仕様の再実装対象ではない（回帰のみ） |

## 確定事項（v0.14.0）

| 項目 | 確定内容 |
|------|----------|
| 構文 | フェンス内テキストの `${…}`。マスタッシュではない |
| 式パーサ | 既存 `parseExpression(source, path, { allowCalls: false })` |
| 評価 | 既存 `evaluateExpression`。`null` / `undefined` → `""`、その他は `String(value)` |
| エスケープ | `\${` → リテラル `${`（バックスラッシュを消費し展開しない） |
| フェンス外 | `${…}` を走査・展開しない |
| フェンス検出 | `` ``` `` / `~~~`、indent ≤3、閉じは同マーカー・長さ以上・info 空（`consumeFenceLine`） |
| 未閉じフェンス | EOF までフェンス内とみなし、その範囲の `${}` は展開する |
| 未閉じ `${` | **`parse_error`**（`unclosed` / unterminated 相当） |
| component 呼び出し | `${foo({…})}` → **`parse_error`**（template literals と同じメッセージ方針） |
| `{{ }}` との順序 | 同一ソース上で先に `{{ }}`、続けてフェンス `${}` |
| each | イテレーション本体でもフェンス `${}` を評価（スコープは当該イテレーション context） |
| 公開 API | 追加なし。内部モジュール（例: `interpolateFenceExpressions`） |

## Phase 1: `interpolateFenceExpressions`（単体）

対象: 新規 `app/src/expr/interpolateFenceExpressions.ts`（関数名は実装時に確定してよい）

- ソース全体を走査し、コードフェンス領域内の `${expr}` だけを評価・置換する
- フェンス外はそのまま通す
- `\${` は展開しない

### interpolateFenceExpressions

#### テスト: 正常系

- `` ```\n# ${title}\n``` `` + context `{ title: "Hello" }` → フェンス内が `# Hello`
- 同一フェンス内に複数 `${a}` `${b}` → それぞれ展開
- `~~~` フェンスでも `` ``` `` と同様に展開
- メンバ・パイプ・三項（例: `${user.name}`、`${title | "fallback"}`、`${flag ? "Y" : "N"}`）が期待どおり
- `.length` / `.toLocaleString(...)` が許可どおり評価される
- フェンス外の `${title}` は **そのまま残る**（前後の本文に混在してもフェンス内だけ置換）
- `\${title}`（フェンス内）→ 出力は `${title}`（展開しない）
- 未束縛 `${missing}` → 空文字（`{{ }}` と同様）
- 未閉じフェンス（閉じマーカーなし）→ EOF までフェンス内として `${}` を展開

#### テスト: 異常系

- フェンス内 `${` の閉じ `}` 欠落 → **`parse_error`**
- フェンス内 `${comp({ x: 1 })}`（登録 component でも）→ **`parse_error`**（calls 不可）
- フェンス内 `${obj.slice(0)}` 等の未許可メソッド → **`parse_error`**
- フェンス内の式構文エラー（例: `${a ? b}`）→ **`parse_error`**

## Phase 2: パイプライン配線（結合）

対象: [renderDocument.ts](../../src/pipeline/renderDocument.ts)、[expandControlStructures.ts](../../src/control/expandControlStructures.ts)

- `renderDocumentBody`: `interpolateExpressions` の直後にフェンス `${}` を実行
- `expandEach`: 各イテレーションで `interpolateExpressions` の直後に同処理（each 束縛を見えるようにする）

### renderDocument（フェンス `${}`）

#### テスト: 正常系

- front matter / API context の値をフェンス内 `${}` で参照できる
- Issue 例相当: 言語タグ付き `` ```markdown\n# ${var_name}\n``` `` が展開される
- フェンス外 `${x}` とフェンス内 `${x}` が混在 → 外は残り、内だけ展開
- フェンス内 `{{ title }}` は従来どおり展開される（マスタッシュ非変更の回帰）

#### テスト: 異常系

- 文書全体レンダー経路でも、フェンス内の未閉じ `${` / 不正式 → **`parse_error`** が伝播する

### expandEach + フェンス `${}`

#### テスト: 正常系

- `each name in items` 本体がフェンスを含み `${name}` を使う → 各行でそのイテレーションの値が入る
- each 本体でマスタッシュとフェンス `${}` を併用できる

#### テスト: 異常系

- each 本体フェンス内の不正 `${}` → **`parse_error`**
