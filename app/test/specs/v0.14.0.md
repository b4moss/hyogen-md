## Phase A: 式パーサ / 評価

対象: `parseExpression`、`evaluateExpression` / `evaluateExpressionAsync`

### parseExpression

- 式文字列を AST に変換する
- リテラル・オブジェクト / 配列・呼び出し引数・テンプレートの構文を扱う
- 不正入力は `parse_error` を投げる

#### テスト: 正常系

- `null` / `undefined` リテラルをパースできる
- 空オブジェクト `{}` / 空配列 `[]` をパースできる
- オブジェクト・配列の末尾カンマを許容する
- ネストしたオブジェクト / 配列をパースできる
- `toLocaleString()` のゼロ引数・複数リテラル引数をパースできる
- 空引数リストの呼び出しをパースできる
- テンプレート内にネストした中括弧付き文字列を含む場合をパースできる

#### テスト: 異常系

- 式の後に余剰トークンがある → `parse_error`
- プロパティ名欠落のメンバーアクセス → `parse_error`
- オブジェクトの `}` / `:` / キー / リテラル値 / `,` または `}` 欠落 → `parse_error`
- 配列の `]` / `,` または `]` 欠落 → `parse_error`
- 不正な数値・未終端文字列・未終端エスケープ → `parse_error`
- 呼び出し引数の `{` / プロパティ名 / `:` / `,` または `}` / `)` 欠落 → `parse_error`
- テンプレートの未終端エスケープ・未終端式 → `parse_error`
- 符号のみで桁のない負数 → `parse_error`

### evaluateExpression

- AST を context 上で評価し値を返す
- 短絡評価・メンバーアクセス・コンポーネント呼び出し・許可メソッドを扱う
- 非対応ノードや未登録呼び出しは規定どおり失敗 / `undefined` を返す

#### テスト: 正常系

- `-` / `*` / `/` を評価できる
- `!==` / `!=` / `<=` / `>` を評価できる
- `&&` / `||` の短絡（右辺未評価）と、左辺が続行条件のときの右辺評価
- 数値・`undefined` へのメンバーアクセスは `undefined`
- `toLocaleString()` の対象が `null` / `undefined` なら `undefined`
- テンプレート部品が `null` / `undefined` のとき当該部品は `undefined` 扱い
- 非認識ノード種別は `undefined`
- 非推奨の `evaluateExpressionAsync` が同期評価へ委譲する

#### テスト: 異常系

- registry / loader / visitStack なしの呼び出し → `parse_error`
- 未登録コンポーネント呼び出し → `parse_error`
- 非対応メソッドノード → `parse_error`

## Phase B: 文パーサ / 実行 / 宣言

対象: `parseStatementList`、`isExecutableBlockSource`、`executeStatementList`、宣言実行

### parseStatementList / isExecutableBlockSource

- hyogen ブロック内の実行文リストをパースする
- 空・コメントのみ・余剰トークン・不正 for/do 構文を拒否する
- `isExecutableBlockSource` は依存収集が実行文ブロックを無視できるか判定する

#### テスト: 正常系

- init / update が空の `for` を実行できる
- for ヘッダ文字列リテラル内の `;` を文区切りと混同しない
- `-=` / `*=` / `/=` 複合代入を実行できる
- `isExecutableBlockSource` は認識できる実行文先頭で `true`、空 / 空白 / コメントのみ / 非実行で `false`

#### テスト: 異常系

- 空文字・コメントのみの文ブロック → `parse_error`
- 有効文の後の余剰トークン / 余剰 `}` → `parse_error`
- 代入での `==`、裸識別子文、識別子なし `++` → `parse_error`
- `const` / `let` の `=` 欠落、`=` 前の識別子欠落 → `parse_error`
- 予約語を宣言・代入の識別子に使用 → `parse_error`
- `for` の `(` / `{` 欠落、ヘッダ内不正トークン、三節形に見せかけた for-of → `parse_error`
- `do` / `do-while` の `{` `}` `while` `(` 欠落・空条件・閉じ `}` なし → `parse_error`
- `=` で始まる文 → `parse_error`

### executeStatementList（更新・複合代入の束縛エラー）

- `++` / 複合代入は `const` 束縛と未宣言変数を拒否する

#### テスト: 異常系

- `const` への `++` / 複合代入 → `parse_error`
- 未宣言変数への `++` / 複合代入 → `parse_error`

### 宣言実行（追加分）

#### テスト: 異常系

- `const` 再宣言 → `parse_error`
- 複数行ブロック内の非対応ディレクティブ → `parse_error`

## Phase C: 設定読込

対象: `loadConfig`、`resolveConfigPath`

### loadConfig / resolveConfigPath

- `hyogen.config.*` を解決・読込し、`input` / パスを正規化する
- 明示 `configFile`、配列 `input`、CJS export、読込失敗を扱う

#### テスト: 正常系

- `input` 配列の各要素を config ディレクトリ基準で解決する
- 明示 `configFile`（相対）で読込できる
- 絶対 `configFile` はそのまま使う
- `default` キーのない CommonJS export を読込できる

#### テスト: 異常系

- 空文字 `input` / 空配列 / 空白要素を含む配列 → `parse_error`
- 存在しない明示 `configFile` → `file_not_found`
- プリミティブを export する CJS → `parse_error`
- モジュール import 失敗 → `load_failed`

## Phase D: 依存収集

対象: `collectDependencies`

### collectDependencies

- ソースから include / component / extend 参照を静的収集する
- 未閉じ・空ブロック・非ディレクティブ複数行を `parse_error` にする
- 複数行の実行文ブロックは依存なしとして無視する

#### テスト: 正常系

- 複数行の実行文ブロックは空の依存リストを返す

#### テスト: 異常系

- 未閉じ hyogen ブロック → `parse_error`
- 空 hyogen ブロック → `parse_error`
- 非対応ディレクティブを含む複数行ブロック → `parse_error`

## Phase E: extend / block 展開

対象: `expandExtendsAndBlocks`

### expandExtendsAndBlocks

- `extend` と子 `block` をレイアウトへマージする
- 孤児 block・複数 extend・循環・レイアウト側 extend・loader 欠落を規定どおり扱う
- include 向け loader の `file_not_found` は `via: extend` に書き換えうる

#### テスト: 正常系

- 自己参照（即時循環）extend は `circular_include` 警告し出力をスキップする

#### テスト: 異常系

- extend なしの孤児 block → `parse_error`
- extend 処理時に loader 未指定 → 通常 Error
- 複数 `extend` → `parse_error`
- loader が `undefined` を返す → 通常 Error
- レイアウト自身が非循環の `extend` を含む → `parse_error`
- include 流用 loader の `file_not_found` → `via: "extend"` に書き換え

## Phase G: HMR hub

対象: `createHmrHub`

### createHmrHub

- WebSocket 風クライアントへ更新パスを配信する
- 空 publish・非 OPEN・send/close 例外を安全に無視 / 除去する

#### テスト: 正常系

- 初期サイズ 0
