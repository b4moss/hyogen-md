## Phase 1: DSL 正規化（IR）

### loadHighlighterDsl（名前は実装で固定）

- `highlighter/dsl/` を読み、バリデーション付きで正規化 IR を返す
- 副作用なし（ファイル読込以外）。不正スキーマはエラー

#### テスト: 正常系

- Given 最小 DSL（マーカー + 予約語のみ）→ Then IR に markers / keywords / embedding 規則が揃う
- Given `reservedWords.ts` と同等の予約語一覧 → Then IR の keyword 集合が一致（漏れ・余剰なし）
- Given 埋め込み規則（フェンス除外、`@hg`/`@@`/`mustache`）→ Then IR に half-open 区間規則が表現される

#### テスト: 異常系

- Given 必須フィールド欠落 → Then スキーマエラー（メッセージにパス）
- Given 未知トークン種別 → Then スキーマエラー
- Given 空の keywords → Then エラー、または明示的に空を許可する場合はテストでロック（推奨: **エラー**）

### normalizeTokenCategories（任意・同モジュールでも可）

- 予約語・演算子・リテラル・コメント・マーカーをカテゴリ別に正規化する
- `else if` のような複数語キーワードを単一トークンとして扱えること

#### テスト: 正常系

- Given `each` / `endeach` / `endif` / `include` / `extend` / `block` / `endblock` / `component` / `as` / `echo` → Then keyword カテゴリ
- Given `else if` → Then 複数語キーワードとして 1 エントリ
- Given `//` と `/* */` → Then comment カテゴリ

#### テスト: 異常系

- Given 重複キーワード定義 → Then エラー、または後勝ち（実装で固定しテストでロック。推奨: **エラー**）
- Given 空文字列トークン → Then エラー

## Phase 2: 埋め込み・領域規則（純ロジック）

Playground の [`findHyogenRegions.ts`](../../docs-site/app/components/playground/editor/findHyogenRegions.ts) 相当を DSL / `highlighter` 側の正とする。挙動は v0.10.0 を踏襲し、厳密ハイライト用に拡張する。

### findHyogenRegions（highlighter 側、または生成前の共有純関数）

- Markdown ソースを受け取り、ハイライト対象の半開区間 `{ from, to, kind }` を返す
- `kind`: `hg-block`（`@hg`…`@endhg`）/ `hg-short`（`@@`…`@@`）
- コードフェンス（`` ``` ``）内は **含めない**
- 不完全ブロックは **捨てる**

#### テスト: 正常系

- Given 通常の `<!-- @hg … @endhg -->` が 1 つ → Then 区間 1 件（`hg-block`）
- Given `<!--@@ const x = 1 @@-->` → Then 区間 1 件（`hg-short`）
- Given フェンス外 1 + フェンス内 1 → Then フェンス外のみ 1 件
- Given hyogen 無し → Then 空配列

#### テスト: 異常系

- Given 未閉じ `@hg` → Then 空（捨てる）
- Given 空文字 → Then 空配列
- Given ネスト風の `@hg` 内側に別 `@hg`（非対応）→ Then 最短一致または仕様固定の挙動をロック（推奨: 現行正規表現の最短一致）

### findMustacheRegions

- フェンス外の `{{ … }}` / `{{{ … }}}` 区間を返す
- 三重を優先し、`{{{ }}}` を `{{` + 余りに分割しない
- 未閉じは捨てる

#### テスト: 正常系

- Given `Hello {{ name }}` → Then 1 件
- Given `{{{ raw }}}` → Then 1 件（三重として）
- Given フェンス内のみ → Then 0 件
- Given `{{ color | "transparent" }}` → Then 1 件（パイプ含むスパン）

#### テスト: 異常系

- Given 未閉じ `{{` → Then 0 件
- Given `{{` のみの文書 → Then 0 件

### findHyogenDirectiveMarks

- 各領域の opener/closer のみ（`@hg` / `@endhg` / `@@`）を返す

#### テスト: 正常系

- Given `hg-block` 1 件 → Then mark 2 件（`@hg` と `@endhg`）
- Given `hg-short` 1 件 → Then mark 2 件（両端 `@@`）

#### テスト: 異常系

- Given 領域 0 件 → Then 空配列

## Phase 3: トークン分類（厳密 hyogen）

### classifyHyogenTokens（名前は実装で固定）

- hyogen ブロック本文（マーカー内側）または mustache 内側の文字列を受け、トークン列 `{ from, to, type }` を返す
- `type` は少なくとも: `keyword` / `comment` / `string` / `number` / `operator` / `punctuation` / `identifier` / `pipe`（または同等。実装で固定）
- mustache モードでは **式のみ**（文キーワードがあっても keyword 扱いにしてよいが、文構造は要求しない）

#### テスト: 正常系

- Given `each items as item` → Then `each` / `as` が keyword、識別子が identifier
- Given `if isNight` … `endif` → Then `if` / `endif` が keyword（`isNight` は identifier）
- Given `include ./x.md` → Then `include` が keyword
- Given `const text = "foo"` → Then `const` keyword、文字列 string、`=` operator
- Given `// comment` と `/* block */` → Then comment
- Given `{{ color | "transparent" }}` の内側 → Then identifier / pipe / string

#### テスト: 異常系

- Given 空文字 → Then 空配列
- Given 未閉じ文字列 `"foo` → Then 実装で固定（推奨: 文書末まで string、または安全に identifier 扱い。テストでロック）
- Given 未知記号のみ → Then punctuation / operator にフォールバックし throw しない

### 予約語一致（回帰ロック）

- IR / classifier の keyword 集合が `RESERVED_WORDS` を **すべて含む**
- 追加でハイライトする語（例: `toc`、`else if`）がある場合は DSL に明示し、本仕様の一覧とテストでロック

#### テスト: 正常系

- Given `RESERVED_WORDS` の各語 → Then keyword として認識
- Given `else if` → Then 複数語 keyword

#### テスト: 異常系

- Given 通常の識別子 `eachItem` → Then keyword にしない（単語境界）
- Given `ENDIF`（大文字）→ Then keyword にしない（DSL は小文字。仕様固定）

## Phase 4: エミッタ（codegen）

共通: `generateAll(ir)`（またはエンジン別 `emitX(ir)`）が `highlighter/generated/` 相当の文字列／ファイル内容を返す。決定的出力（同一 IR → 同一出力）。

### emitTextMate（Shiki）

- TextMate grammar JSON（`hyogen` および Markdown 埋め込みに必要なルール）を生成する
- repository / patterns にマーカー・予約語・コメント・文字列が含まれる

#### テスト: 正常系

- Given 正規 IR → Then 妥当な JSON（`scopeName` / `patterns` / `repository` 存在）
- Given 予約語一覧 → Then grammar 文字列に各予約語が含まれる
- Given golden fixture → Then スナップショット一致

#### テスト: 異常系

- Given 空 IR → Then エラー
- Given keywords 欠落 IR → Then エラー

### emitPrism

- Prism 言語定義（関数または JSON 相当）を生成する
- `Prism.languages.hyogen` に載る形、または import 可能なモジュール文字列

#### テスト: 正常系

- Given 正規 IR → Then `each` / `@hg` / 文字列パターンを含む定義
- Given golden → Then スナップショット一致

#### テスト: 異常系

- Given 空 IR → Then エラー

### emitHighlightJs

- highlight.js 言語定義モジュールを生成する
- `name: 'hyogen'`（または同等）と keywords / contains を持つ

#### テスト: 正常系

- Given 正規 IR → Then keywords に予約語が含まれる
- Given golden → Then スナップショット一致

#### テスト: 異常系

- Given 空 IR → Then エラー

### emitCodeMirror

- CodeMirror 6 向け定義（StreamLanguage または同等）と、Markdown 埋め込み用拡張の組み立てに必要な export を生成する
- JS `javascriptLanguage` overlay に依存しない

#### テスト: 正常系

- Given 正規 IR → Then export 名がドキュメントどおり（実装で固定しテスト）
- Given サンプル `@hg each x\n@endhg` を生成 Language でパース／トークナイズ → Then `each` が keyword 相当
- Given golden → Then スナップショット一致

#### テスト: 異常系

- Given 空 IR → Then エラー
- Given 不正 IR → Then エラー（部分生成しない）

### emitMonaco

- Monaco Monarch 言語定義 JSON（または JS）を生成する

#### テスト: 正常系

- Given 正規 IR → Then `tokenizer` / `keywords`（または同等）が存在
- Given golden → Then スナップショット一致

#### テスト: 異常系

- Given 空 IR → Then エラー

### generate.mjs（CLI 結合）

- DSL を読み、全エンジン成果物を `generated/` に書き出す
- 終了コード 0。失敗時は非 0 と stderr

#### テスト: 正常系

- Given リポジトリの正本 DSL → Then 5 系統の成果物が存在し、再実行で内容が安定（バイト一致または正規化後一致）

#### テスト: 異常系

- Given 壊した DSL → Then 非 0 終了、`generated/` を中途半端に壊さない（書き込み前検証、または temp 置換。実装で固定）

## Phase 5: Golden / トークン契約

### fixtures（想定）

```
highlighter/test/fixtures/
  basic-hg-block.md          # @hg const / if / each / include
  shorthand.md               # @@ … @@
  mustache.md                # {{ }} / {{{ }}} / pipe
  fence-noise.md             # フェンス内に偽 @hg / {{ }}
  comments.md                # // と /* */
  reserved-all.md            # 主要予約語を網羅
```

### assertTokenContract（名前は実装で固定）

- 入力 Markdown（または hyogen 断片）と期待トークン（種別＋該当文字列）の契約を検証する
- エンジン共通の **意味トークン**（keyword `each` 等）を優先し、scope 名の細部差はアダプタで吸収してよい

#### テスト: 正常系

- Given `basic-hg-block.md` → Then `const` / `if` / `each` / `include` / `endif` / `endeach` が keyword
- Given `mustache.md` → Then mustache 区間が識別され、内側の pipe / string が期待どおり
- Given `fence-noise.md` → Then フェンス内は hyogen keyword 契約の対象外（0 件）

#### テスト: 異常系

- Given 期待キーワードが欠落する壊れた生成物 → Then 契約テスト失敗
- Given フェンス除外が壊れた定義 → Then `fence-noise` 契約が失敗すること（回帰検知）

エンジン別の薄いアダプタテスト（任意だが推奨）:

| エンジン | 検証の最低ライン |
|----------|------------------|
| TextMate / Shiki | grammar を tokenizer で走らせ、scope に keyword 相当が付く |
| Prism | `Prism.highlight` 相当、または regex 定義の存在＋サンプルマッチ |
| highlight.js | `hljs.highlight(..., { language: 'hyogen' })` が keyword class を含む |
| CodeMirror 6 | StreamLanguage / 拡張で keyword トークンが取れる |
| Monaco | Monarch 定義の keywords / tokenizer ルートがサンプル行にマッチ |

すべてをフル統合しなくてよいが、**少なくとも CodeMirror 6 と TextMate（または highlight.js）の 2 系統**でトークン契約を自動検証する。残りは golden スナップショット必須。

## #125 コードフェンス内 `${}` インターポレーション

[roadmap v0.14.0](../../docs/roadmap.md) の実装範囲に対応する。Issue [#125](https://github.com/b4moss/hyogen-md/issues/125)。

製品仕様の正本は実装後に [variables.md](../../docs/specs/variables.md) / [pipeline.md](../../docs/specs/pipeline.md) / [dsl.md](../../docs/specs/dsl.md) へ転記する（Agent ブランチでは `docs-agent-note/` に差分案）。式の意味は既存の `@hg` テンプレートリテラル内 `${}`（[dsl.md](../../docs/specs/dsl.md)「テンプレートリテラル内の式」）に揃える。

---

## スコープ

- **コードフェンス内の `${expr}` 展開** — JS テンプレートリテラルと同型の振る舞い（本文マスタッシュ `{{ }}` とは別系統）
- 対象フェンス: `` ``` `` および `~~~`（CommonMark 寄りの開閉規則。実装は `createFenceState` / `consumeFenceLine` を再利用）
- 式: 許可式のみ。`.toLocaleString` / `.length` 可。**component 呼び出し不可**（`allowCalls: false`）
- エスケープ: `\${` は展開しない（JS と同じ）
- パイプライン配線: `interpolateExpressions`（`{{ }}`）の直後。`expandEach` 内でも同順（each 束縛をフェンス内から参照可能に）
- v0.13.0 回帰維持

## スコープ外（v0.14.0 / #125）

| 項目 | 扱い |
|------|------|
| フェンス**外**の本文 `${}` | リテラルのまま。本 Issue 対象外 |
| `{{ }}` / `{{{ }}}` の挙動変更 | 対象外（フェンス内でも現状どおり展開される） |
| Playground / docs-site のハイライト | 別 Issue |
| 公開 API シグネチャ変更 | なし |
| `@hg` 内 `` `…${}…` `` | 既存（v0.7）。本仕様の再実装対象ではない（回帰のみ） |

## 確定事項（v0.14.0）

| 項目 | 確定内容 |
|------|----------|
| 構文 | フェンス内テキストの `${…}`。マスタッシュではない |
| 式パーサ | 既存 `parseExpression(source, path, { allowCalls: false })` |
| 評価 | 既存 `evaluateExpression`。`null` / `undefined` → `""`、その他は `String(value)` |
| エスケープ | `\${` → リテラル `${`（バックスラッシュを消費し展開しない） |
| フェンス外 | `${…}` を走査・展開しない |
| フェンス検出 | `` ``` `` / `~~~`、indent ≤3、閉じは同マーカー・長さ以上・info 空（`consumeFenceLine`） |
| 未閉じフェンス | EOF までフェンス内とみなし、その範囲の `${}` は展開する |
| 未閉じ `${` | **`parse_error`**（`unclosed` / unterminated 相当） |
| component 呼び出し | `${foo({…})}` → **`parse_error`**（template literals と同じメッセージ方針） |
| `{{ }}` との順序 | 同一ソース上で先に `{{ }}`、続けてフェンス `${}` |
| each | イテレーション本体でもフェンス `${}` を評価（スコープは当該イテレーション context） |
| 公開 API | 追加なし。内部モジュール（例: `interpolateFenceExpressions`） |

## Phase 1: `interpolateFenceExpressions`（単体）

対象: 新規 `app/src/expr/interpolateFenceExpressions.ts`（関数名は実装時に確定してよい）

- ソース全体を走査し、コードフェンス領域内の `${expr}` だけを評価・置換する
- フェンス外はそのまま通す
- `\${` は展開しない

### interpolateFenceExpressions

#### テスト: 正常系

- `` ```\n# ${title}\n``` `` + context `{ title: "Hello" }` → フェンス内が `# Hello`
- 同一フェンス内に複数 `${a}` `${b}` → それぞれ展開
- `~~~` フェンスでも `` ``` `` と同様に展開
- メンバ・パイプ・三項（例: `${user.name}`、`${title | "fallback"}`、`${flag ? "Y" : "N"}`）が期待どおり
- `.length` / `.toLocaleString(...)` が許可どおり評価される
- フェンス外の `${title}` は **そのまま残る**（前後の本文に混在してもフェンス内だけ置換）
- `\${title}`（フェンス内）→ 出力は `${title}`（展開しない）
- 未束縛 `${missing}` → 空文字（`{{ }}` と同様）
- 未閉じフェンス（閉じマーカーなし）→ EOF までフェンス内として `${}` を展開

#### テスト: 異常系

- フェンス内 `${` の閉じ `}` 欠落 → **`parse_error`**
- フェンス内 `${comp({ x: 1 })}`（登録 component でも）→ **`parse_error`**（calls 不可）
- フェンス内 `${obj.slice(0)}` 等の未許可メソッド → **`parse_error`**
- フェンス内の式構文エラー（例: `${a ? b}`）→ **`parse_error`**

## Phase 2: パイプライン配線（結合）

対象: [renderDocument.ts](../../src/pipeline/renderDocument.ts)、[expandControlStructures.ts](../../src/control/expandControlStructures.ts)

- `renderDocumentBody`: `interpolateExpressions` の直後にフェンス `${}` を実行
- `expandEach`: 各イテレーションで `interpolateExpressions` の直後に同処理（each 束縛を見えるようにする）

### renderDocument（フェンス `${}`）

#### テスト: 正常系

- front matter / API context の値をフェンス内 `${}` で参照できる
- Issue 例相当: 言語タグ付き `` ```markdown\n# ${var_name}\n``` `` が展開される
- フェンス外 `${x}` とフェンス内 `${x}` が混在 → 外は残り、内だけ展開
- フェンス内 `{{ title }}` は従来どおり展開される（マスタッシュ非変更の回帰）

#### テスト: 異常系

- 文書全体レンダー経路でも、フェンス内の未閉じ `${` / 不正式 → **`parse_error`** が伝播する

### expandEach + フェンス `${}`

#### テスト: 正常系

- `each name in items` 本体がフェンスを含み `${name}` を使う → 各行でそのイテレーションの値が入る
- each 本体でマスタッシュとフェンス `${}` を併用できる

#### テスト: 異常系

- each 本体フェンス内の不正 `${}` → **`parse_error`**
