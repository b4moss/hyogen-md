- **`echo <式>`** — `@hg` / `@@` ブロック内の文。評価結果を当該 HTML コメント位置の本文へ展開（置換）する（Issue #53）
- **docs-site 式リファレンス** — `.length` / `echo` の記載更新（Issue #47。アプリ自動テスト外。手動・内容レビュー）

## 確定事項（v0.12.0）

| 項目 | 確定内容 |
|------|----------|
| `.length` の扱い | **プロパティ参照**（`object.length`）。許可メソッド一覧には載せない |
| `.length` 対象 | 配列・文字列で要素数 / 文字数を返す。`null` / `undefined` レシーバ → `undefined` |
| 未許可メソッド | `.slice()` / `.map()` 等は従来どおり **`parse_error`**（`unsupported method`） |
| `.toLocaleString(...)` | 引き続き唯一の許可メソッド（回帰） |
| `echo` 構文 | `echo <式>`（識別子・メンバ・リテラル等、既存式パーサ） |
| `echo` 予約語 | `echo` を識別子として使えない（[dsl.md](../../docs/specs/dsl.md) 予約語） |
| `echo` 配置 | `@hg`…`@endhg` / `@@`…`@@` の **実行文ブロック**（pipeline step 2a `executeDeclarations`） |
| `echo` 効果 | 当該 hyogen コメント全体を、ブロック内の echo 出力文字列で **置換** |
| 複数 `echo` | 同一ブロック内は評価順に **連結**（区切り文字なし） |
| ループ内 `echo` | `for` / `do…while` 本体の `echo` も連結に含める |
| `echo` のみのブロック | `<!--@@ echo greet @@-->` も実行対象（`isExecutableBlockSource` に `echo`） |
| `const` + `echo` | 宣言実行後に echo。コメントは echo 結果で置換（宣言ブロックは残さない） |
| nullish | `echo` の式結果が `null` / `undefined` → **空文字**（`{{ }}` と同じ） |
| 後段補間 | 置換後の本文は step 6 `interpolateExpressions` の対象になる |
| `@@` 等価 | `echo` についても `@hg` と `@@` は等価 |

## Phase 1: 許可プロパティ `.length`

対象: [evaluateExpression.ts](../../src/expr/evaluateExpression.ts)（`getPropertyValue`）、式のメンバアクセス経路、[parseExpression.ts](../../src/expr/parseExpression.ts)（メソッド拒否は既存）

### getPropertyValue / evaluateExpression（member `.length`）

- レシーバが配列なら `.length` で要素数を返す
- レシーバが文字列なら `.length` で文字数を返す（v0.12 で明示対応）
- レシーバが `null` / `undefined` なら `undefined`
- 危険キー（`__proto__` 等）は従来どおり拒否（`.length` とは独立）

#### テスト: 正常系

- context `{ items: [1, 2, 3] }` で式 `items.length` → `3`
- context `{ s: "abc" }` で式 `s.length` → `3`
- context `{ obj: { length: 99 } }` で式 `obj.length` → `99`（通常のプロパティ参照）
- `{{ items.length }}` を含むドキュメント → 本文に `3` が展開される

#### テスト: 異常系

- `items.slice(0, 1)` → **`parse_error`**（`unsupported method: slice()`）
- `items.length()` → **`parse_error`**（メソッドとしての `length` は未許可）
- `obj.__proto__` → **`forbidden_property_access`**（既存回帰）

## Phase 2: `echo` 文のパース

対象: [parseStatement.ts](../../src/logic/parseStatement.ts)、[types.ts](../../src/types.ts)、[reservedWords.ts](../../src/logic/reservedWords.ts)

### parseStatementList / isExecutableBlockSource（echo）

- `echo` に続く式をパースし `{ kind: "echo"; expr: ExprNode }` を返す
- `isExecutableBlockSource` が `^echo\b` で真になる
- `echo` は予約語（`const echo = 1` 等は不可）

#### テスト: 正常系

- `echo greet` → statement kind `echo`、expr は identifier `greet`
- `echo items.length` → expr は member `items` / `length`
- `echo "hello"` → expr は literal `"hello"`
- `const greet = "Hi"\necho greet` → `const` と `echo` の 2 文
- ソース先頭が `echo …` のみ → `isExecutableBlockSource` が `true`

#### テスト: 異常系

- `echo` のみ（式なし）→ **`parse_error`**
- `const echo = 1` → **`parse_error`**（予約語）
- `echo (` で式が未完結 → **`parse_error`**

## Phase 3: `echo` の実行と本文置換

対象: [executeStatement.ts](../../src/logic/executeStatement.ts)、[executeDeclarations.ts](../../src/logic/executeDeclarations.ts)

### executeStatement（echo）

- 式を `evaluateExpression` し、文字列化して出力バッファへ追記する
- `null` / `undefined` → `""`
- それ以外は `String(value)`（`{{ }}` と同様）

#### テスト: 正常系

- context `{ greet: "Hello world!" }` で `echo greet` → 出力 `"Hello world!"`
- `echo null` / 未定義識別子で値が `undefined` → 出力 `""`
- `echo 42` → 出力 `"42"`
- 同一リストで `echo "a"` のあと `echo "b"` → 連結 `"ab"`

#### テスト: 異常系

- （式評価の既存エラーに委譲）危険キーを含む式 → **`forbidden_property_access`**
- 未許可メソッドを含む式 → **`parse_error`**

### executeDeclarations（ブロック置換）

- 実行対象ブロックに echo 出力がある場合、HTML コメント全体をその文字列で置換する
- echo が無く宣言のみの場合は従来どおりコメント削除（`joinRemovalSeam`）
- `@hg` と `@@` で同一結果

#### テスト: 正常系

- 入力:

  ```markdown
  <!--
  @hg
  const greet = "Hello world!"
  echo greet
  @endhg
  -->
  ```

  → 出力本文: `Hello world!`（コメントは残らない）

- 前後テキストあり: `A\n<!--@hg\necho "X"\n@endhg-->\nB` → `A\nX\nB`（改行シームは既存 `joinRemovalSeam` / 置換方針に整合）
- 宣言ブロックと `<!--@@ echo greet @@-->` の併用（Issue #53 例）→ 宣言は削除、echo 位置に値
- `for` 内で複数回 `echo` → 反復分が連結されてブロック位置に挿入

#### テスト: 異常系

- 実行不能な混在（例: 複数行で `include` と `echo` を同一ブロック）→ 既存規則に従い **`parse_error`**
- step 2a で消化されず残った単独不明ディレクティブ → 既存どおり `executeHgBlocks` で **`parse_error`**
