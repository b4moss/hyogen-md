# v0.12.0 テスト仕様書

[roadmap v0.12.0](../../docs/roadmap.md) の実装範囲に対応する。製品仕様は [docs/specs/toc.md](../../docs/specs/toc.md) / [pipeline.md](../../docs/specs/pipeline.md) / [api.md](../../docs/specs/api.md) が正。Issue #42。

## スコープ

- **TOC 専用ヘルパ** — `toc` / `toc(N)` を Markdown 目次に展開（ビルトイン関数は導入しない）
- 構文 3 形式（HTML コメント内）: `<!--@@ toc(3) @@-->` / `<!--@hg toc(3) @hg-->`（`@hg`…`@endhg` 形も等価）
- 見出し抽出（ATX / Setext）、除外領域、アンカー ID、ネストリスト出力
- パイプライン step 7（`{{ }}` 評価直後・`stripHgComments` 前）
- 早期パススルー（`executeHgBlocks` / `collectDependencies` / 宣言実行で `unsupported` にしない）
- v0.11.0 回帰維持

## スコープ外（v0.12.0）

- TOC の HTML 化
- docs-site の TOC ページ（Issue #44）
- ビルトイン関数としての `toc`
- 公開 API（`renderServer` / `renderClient` / `build`）のシグネチャ変更
- Playground 専用 UI

## 確定事項（v0.12.0）

| 項目 | 確定内容 |
|------|----------|
| 配置 | パイプライン内自動処理。公開 API 追加なし（内部モジュール `app/src/toc/`） |
| 構文 | HTML コメント内の hyogen ブロック 1 行: `toc` または `toc(N)` |
| `N` | 整数 **1〜6**（最大見出しレベル）。省略時 **6** |
| 不正 `N` | **`parse_error`**（負数・小数・0・7 以上・非数値・余分な引数） |
| 抽出タイミング | extend / include / component / if / each / `{{ }}` **完了後**の最終 Markdown |
| 抽出対象 | ATX（`#`〜`######`）と Setext（`===`→h1、`---`→h2）。レベル ≤ `N` のみ |
| 除外 | フェンス付きコード（`` ``` `` / `~~~`）、残存 hyogen ブロック、HTML コメント内部の見出し |
| TOC 位置 | 文書全体を対象（ディレクティブ位置に依存しない）。同一ページに複数可（各々独立に `N` で生成） |
| 出力 | ネストした Markdown リスト + `[テキスト](#anchor)`。0 件は **空文字**（警告なし） |
| ネスト | その TOC に含まれる見出しの最小レベルを基準に、インデント `(level - minLevel) * 2` スペース |
| テキスト | プレーン化（`**bold**` 等の装飾除去）。明示 ID `{#id}` は本文から除去しアンカーに使用 |
| アンカー | 明示 `{#id}` 優先。否则 GitHub 互換（小文字・空白→ハイフン・記号除去）。文書内重複は `-1`, `-2`, … |
| 置換 | ディレクティブブロック全体を TOC Markdown に置換（`joinRemovalSeam`） |
| エラーコード | 引数不正は既存どおり **`parse_error`**（専用 code を増やさない） |

## Phase 1: parseTocDirective / isTocDirectiveLine

### parseTocDirective

- hyogen ブロック inner（または 1 行ソース）を入力に、`{ maxLevel: number }` を返す
- `toc` → `maxLevel: 6`、`toc(N)` → `maxLevel: N`（1〜6）
- 不正な引数・形式は `createHyogenError({ code: "parse_error", path?, details: { message } })` を投げる

#### テスト: 正常系

- `"toc"` → `{ maxLevel: 6 }`
- `"toc(1)"` … `"toc(6)"` → それぞれの `maxLevel`
- 前後空白のみ（`extractHgBlockLines` 後の 1 行）でも同様にパースできる
- `@hg` / `@@` マーカーを含むブロック文字列から inner を取り出した結果でも同様（パーサは inner 行を対象）

#### テスト: 異常系

- `toc(0)` / `toc(7)` / `toc(-1)` → `parse_error`
- `toc(3.5)` / `toc(1.0)`（小数）→ `parse_error`
- `toc(abc)` / `toc()`（空引数）→ `parse_error`
- `toc(3, 4)` / `toc 3`（非対応形式）→ `parse_error`
- 複数行 inner → `parse_error`（単一ディレクティブのみ）

### isTocDirectiveLine

- 1 行が toc ディレクティブかどうかを判定する（早期パススルー用）
- 構文として toc らしい行なら true（引数の妥当性は `parseTocDirective` 側でエラーにする）

#### テスト: 正常系

- `"toc"` / `"toc(3)"` → `true`
- `"include ./x.md"` / `"if true"` / `"const x = 1"` → `false`

#### テスト: 異常系

- （判定関数のため異常系は省略可。空文字 → `false`）

## Phase 2: extractHeadings / githubHeadingSlug

### extractHeadings

- Markdown 文字列から見出し配列 `{ level, text, explicitId? }[]` を文書順で返す
- ATX（行頭 `#`〜`######` + 空白）と Setext（テキスト行 + `===` / `---`）を対象
- フェンス（`` ``` `` / `~~~`）、hyogen ブロック、HTML コメントの **内部** はスキップ

#### テスト: 正常系

- ATX h1〜h6 がレベル・テキストどおり抽出される
- Setext: `Title\n===` → level 1、`Title\n---` → level 2
- `## Title {#my-id}` → `text: "Title"`, `explicitId: "my-id"`
- フェンス内の `# Not a heading` は含まれない（`` ``` `` と `~~~` の両方）
- `<!-- comment with # Heading -->` 内は含まれない
- `<!--@@ const x = 1 @@-->` 等の hyogen ブロック内の見出し行は含まれない
- toc ディレクティブ自身（HTML コメント）内に見出しが無くても、周囲の本文見出しは抽出される

#### テスト: 異常系

- 見出しなし → `[]`（エラーにしない）
- 閉じられていないフェンス内は仕様どおり「フェンス内部」として扱い、中の見出しを採用しない（実装で固定しテストする）

### githubHeadingSlug

- 見出しテキスト（と任意の明示 ID）からアンカー文字列を返す
- 明示 ID があればそれを使い、無ければ GitHub 互換規則で生成
- 同一文書内の重複カウンタを渡せる（または生成器オブジェクト）

#### テスト: 正常系

- `"Page Title"` → `"page-title"`
- 明示 ID `"my-id"` → `"my-id"`（小文字化等の要否は GitHub / 明示値優先の方針で固定。明示はそのまま採用）
- 空白・記号を含む見出しがハイフン連結の slug になる
- 同一 slug が 2 回目 → `"page-title-1"`、3 回目 → `"page-title-2"`（GitHub 互換の重複付与）
- 日本語見出しでも GitHub 互換（文字が残る / 除去される規則をテストで固定）

#### テスト: 異常系

- 空文字テキスト → 空 slug またはフォールバック（実装で 1 つに固定しテスト）

## Phase 3: formatTocMarkdown

### formatTocMarkdown

- 見出し配列と `maxLevel` を受け、TOC の Markdown 文字列を返す
- レベル ≤ `maxLevel` のみ採用
- ネスト: `minLevel = min(採用見出しの level)`、各行のインデントは `(level - minLevel) * 2` スペース + `- [text](#anchor)`
- 見出しテキストはプレーン化してから表示・slug 生成（明示 ID がある場合は slug に明示を優先）
- 採用 0 件 → `""`

#### テスト: 正常系

- h1 / h2 / h3 入力・`maxLevel: 3` で次の形（ネスト規則どおり）:

```markdown
- [Page Title](#page-title)
  - [Section A](#section-a)
    - [Sub A-1](#sub-a-1)
  - [Section B](#section-b)
```

- `maxLevel: 2` のとき h3 行が出ない
- 装飾付き見出し `## **Bold** and \`code\`` → 表示テキストはプレーン、リンクもプレーン基準
- 明示 ID 付き → `[Title](#my-id)`
- 重複見出し → アンカーに `-1`, `-2` が付く

#### テスト: 異常系

- 空配列 → `""`（警告・エラーなし）
- すべて `level > maxLevel` → `""`

## Phase 4: expandToc

### expandToc

- 最終 Markdown（式評価後を想定）を入力に、toc ディレクティブを TOC Markdown に置換した文字列を返す
- `scanHgBlocks` で toc ブロックを列挙し、各々 `parseTocDirective` → 見出しは **置換前の全文**から 1 回抽出して各 `N` で format
- 複数 toc はそれぞれ独立（異なる `N` なら内容が異なり得る）
- toc が無い文書はそのまま返す
- 置換は `joinRemovalSeam` で空白を整える

#### テスト: 正常系

- `<!--@@ toc(3) @@-->` がネストリストに置換され、元の見出し本文は残る
- `<!--@hg toc(2) @hg-->` / `@endhg` 形も同様
- 同一ページに `toc(2)` と `toc(3)` → それぞれ異なる深さの TOC
- 見出し 0 件の文書で toc → ディレクティブが空に消え、エラー・警告なし
- toc 無し → 入力と同一

#### テスト: 異常系

- `<!--@@ toc(0) @@-->` → `parse_error`（中断）
- `<!--@@ toc(7) @@-->` → `parse_error`
- `<!--@@ toc(abc) @@-->` → `parse_error`

## Phase 5: 早期パススルー

### executeHgBlocks / collectDependencies / executeDeclarations

- 本文に toc ディレクティブだけ（または include 等と混在）あっても、step 2〜4 相当で **`unsupported hyogen directive` にしない**
- toc ブロックは除去・マーカー化せず残す（expandToc まで到達させる）

#### テスト: 正常系

- `executeHgBlocks` に `<!--@@ toc(3) @@-->` のみ → source に toc が残る / directives に toc を含めない
- `collectDependencies` が toc のみのファイルで空依存を返し、throw しない
- 宣言実行パスで toc 行が残っていても throw しない

#### テスト: 異常系

- 不正 toc（`toc(0)`）は早期パススルーでは落とさず、**expandToc 到達時**に `parse_error`（またはパースを早期に行う実装ならその時点）。いずれかに固定しテストする — **本仕様では expandToc（step 7）で検証する**

## Phase 6: 結合（renderDocument / renderServer）

### renderDocument / renderServer（TOC）

- フルパイプラインで toc が step 7 相当で展開される
- include / if / `{{ }}` の結果が見出しに反映される
- デフォルトでは toc の hyogen コメント痕跡は最終出力に残らない（strip 後）

#### テスト: 正常系

- fixture `basic/page.md` を `renderServer`（または `renderDocument`）→ TOC リストと本文見出しが両方含まれる
- `pipeline/with-include.md` — include 先の見出しが TOC に含まれる
- `pipeline/with-if.md` — 偽分岐内の見出しは TOC に含まれない
- `pipeline/with-expr.md` — `{{ }}` で生成された見出しテキストが TOC に反映される
- `preserveHgComments: true` でも toc ディレクティブ自体は既に置換済みのため、toc マーカーは残らない（TOC 本文は残る）

#### テスト: 異常系

- 不正 `toc(0)` を含む文書 → Promise reject / throw、`parse_error`
- （API シグネチャ非変更）`renderServer` / `renderClient` / `build` のオプション型に toc 専用キーが無いことを型・呼び出しで確認（回帰）
